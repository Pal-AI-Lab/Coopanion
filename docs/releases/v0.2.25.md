# Coopanion v0.2.25

**修复 0.2.24 上第一次上下文交接之后不再交接;交接压不下上下文时只再试一次，之后停止，日志里写明该改哪些设置**

## 修复

- **第一次上下文交接之后不再交接**:0.2.24 上，Coo 交接过一次之后不再提醒、也不再交接，上下文一路涨到模型上限，重启应用才恢复一次。现在每次越过交接点都照常先提醒、再交接(感谢 @YihaoYin-Nue、@TOKITOKI422、@zwpnpkzk4v-source,#842)。
- **交接压不下上下文时的处理**:交接之后的上下文由系统提示词、工具清单和交接笔记组成，装的扩展多、「上下文阶段预算」设得小或软阈值比例调得低时，它本身就可能高于交接点。现在按交接后第一次请求里模型服务数出的输入来判断交接有没有压下来，只再试一次：
  - 第一次没压下来:工作区清单改成只列顶层，再交接一次。
  - 再交接一次还是没压下来：停止自动提醒和交接，上下文继续增长，到模型的输入上限时再强制交接;上下文回到交接点以内，或者改了「上下文阶段预算」「软阈值比例」后恢复。
  - 这两步各在运行日志(数据目录的 `logs\core.log`)里记一条，第一步是警告、第二步是错误，写明可以怎么办：调大「上下文阶段预算」会抬高交接点;精简提示词和常驻的记忆文件、停用不需要的扩展会减小交接后的上下文。

  0.2.24 里这个判断读的是只含系统提示词的本地估算，交接后的上下文真的高于交接点时拦不住，会接连交接(感谢 @chloveln、@a530682882,#713;@TOKITOKI422,#842)。

## 改动

- **进程崩溃时留下转储文件**:Coopanion 的任何一个进程崩溃时，在数据目录的 `Crashpad\reports` 里留下一个 `.dmp` 文件，不上传。报崩溃问题时可以把它附上(感谢 @qinmuxue87-gif,#840)。
- **刚启动、刚交接时的上下文读数**:模型服务还没报过用量时(启动后和每次交接后的第一次请求之前),上下文读数把工具清单也估算进去，比以前高一些;第一次请求返回后仍以模型服务数出的为准。
- **cortico 子模块升到 v0.2.19**。
- **Minecraft World 0.2.19**:在扩展市场或扩展详情里把 Minecraft World 更新到 0.2.19、重启进程后，寻路经过已经卸载的区块时不再让引擎进程崩溃(连带 MC 服务端和观察者客户端重启)。
